# vague

[English](README.md)

원하는 게 반쯤만 정해졌을 때 쓰는 논의 스킬입니다. Claude Code와 Codex에서 동작합니다.

이 일이 코드 작업인지 분석/설계인지, 논의만 할지 파일까지 고칠지를 스킬이 판단하고, 판단마다 한 줄 이유를 붙입니다. 사용자는 판단을 뒤집는 식으로 방향을 잡습니다.

## 언제 쓰나

- 뭔가 만들고 싶은데 모양이 잡히지 않을 때
- 코드 작업인지 기획/분석인지조차 확실하지 않을 때
- 원인 분석이나 시스템 설계의 방향을 잡고 싶을 때

## 동작 방식

- 첫 응답에서 사용자의 말을 **목표 / 이미 정한 것 / 모르는 것 / 사용자의 감**으로 나눕니다.
- **성격**(코드 생성 / 분석·설계)과 **단계**를 판단합니다.
  - 요구사항 불명확 → 결정에 가장 영향이 큰 질문만 선택지로 묻습니다
  - 모양에 대한 감만 있음 → 해석 2–3개를 미리보기로 보여줍니다
  - 선택지를 모름 → 성격이 다른 접근들을 추천 없이 펼칩니다
  - 요구사항 충분 → 마무리를 제안합니다
- 적은 내용이 원하는 것과 달라 보이거나 틀려 보이면 이유와 함께 짚고, 결정은 사용자에게 맡깁니다.
- 사용자가 확신하지 못하는 부분만 판단하고, 이미 분명한 부분은 "이미 정한 것"에 둡니다. 대화 중에 원하는 것이 바뀌면 다시 나누고 다시 판단합니다.
- 조사 깊이, 행동(논의만 / 파일 수정 / 문서 작성), 결과물은 필요해질 때 판단합니다.
- 사용자의 언어로 답합니다. 논의가 끝날 때까지 모든 응답 끝에 **요구사항 원장**(확정 / 후보 / 기각)을 갱신해 붙입니다.
- 파일 수정 같은 변경은 스킬이 행동 판단(무엇을 어디에 바꾸는지)을 제시하고 사용자가 확인한 뒤에만 합니다. 되묻거나 아이디어를 스케치하는 것은 승인이 아닙니다. 읽기와 조사는 확인 없이 합니다.
- 확인받은 행동을 마치거나, 사용자가 그만하자고 하면 논의가 끝납니다.
- 마무리할 때 다른 사람이나 에이전트가 이어서 만들 수 있게 **인수인계**를 요청할 수 있습니다. 수용 기준을 auto(각각 검증 방법 포함)와 human으로 나누고, 제약, 구현 전에 확인할 가정(A1, A2, … ID 부여), 기각 항목에서 온 non-goals를 적고, 같은 내용을 JSON 블록으로도 붙입니다. 모든 요구사항은 검증할 수 있어야 하므로 "자연스럽게" 같은 표현은 수치 기준이나 사람 확인 항목으로 바꿉니다. 어디에 남길지, 무엇을 auto로 볼지의 기준은 프로젝트 관례(CLAUDE.md, memory)를 따릅니다.
- 바로 답할 사람이 없을 때(무인 실행, 이슈 스레드) 추측해서 진행하지 않고, 질문을 번호 붙인 선택지로 한 번에 남기고 멈춥니다.

판단 뒤집기 (의미로 알아들으며, 언어는 상관없습니다):

| 이렇게 말하면 | 이렇게 됩니다 |
|---|---|
| "아니 그거 말고" / "이건 아냐" | 해석을 다시 보여줍니다 |
| "선택지부터 보여줘" | 선택지를 펼칩니다 |
| "네가 정해" | 지금 걸린 질문을 스킬이 정하고, 가정으로 표시한 뒤 계속합니다. 남은 질문이 없으면 바로 행동 판단으로 갑니다 |
| "정리해" | 요구사항 → 장단점 표 → 결정과 이유 |
| "그만" / "됐어" | 논의를 끝냅니다 |

## 예시

vague로 vague 자체를 고쳤던 실제 세션을 줄인 것입니다.

**사용자:** `/vague:vague vague는 지금 코드 작업을 전제로 하는데, 분석·아이디어·기획 전용으로도 쓰고 싶어`

> - **목표:** 코드 작업을 전제하지 않는 분석·아이디어·기획용 버전
> - **이미 정한 것:** 지금 vague와 별개인 "전용 버전", 범위는 분석·아이디어·기획
> - **모르는 것:** 무엇을 분석하는지, 조사를 얼마나 깊게 할지, 결과를 어디에 남길지, 지금 vague와의 관계
> - **감:** 지금 뼈대에서 코드 전용 부분만 갈아 끼운 것
>
> **판단: 요구사항 불명확.** "분석"이 코드 분석이면 조사 제한을 풀어야 하고, 아니면 그 제한이 아예 필요 없어서 규칙이 정반대로 갈립니다.
>
> *(선택지 질문 4개: 분석 대상 / 결과 위치 / 기획 범위 / 별도 스킬 vs 내장)*

**사용자:** 별도 스킬 말고 vague 안에 넣어줘. 나도 둘 중 뭘 골라야 할지 모를 수 있으니까.

> 추천이 바뀝니다: 별도 스킬 대신 vague에 내장하고, 성격도 vague가 판단합니다.
>
> **판단: 모양에 대한 감만 있음.** 후보 A / B / C를 미리보기로 보여드립니다(추천 없음).
>
> **요구사항 원장**
> - 확정: vague에 내장, 조사 깊이는 주제에 따라 판단, …
> - 후보: 접근 A / B / C, 대화 중 성격 전환 (가정), …
> - 기각: 별도 스킬

**사용자:** 파일을 고칠지 논의만 할지도 논의하고 판단해서 정했으면 좋겠어.

> 결정 하나가 뒤집힙니다. 고정이던 "논의만" 규칙이 판단 항목이 되어, 뼈대가 "고정 규칙 + 판단 항목"이 됩니다.
>
> *(마무리: 요구사항 → 장단점 표 → 결정과 이유 → 바뀐 부분)*
>
> **행동 판단:** SKILL.md를 이 초안으로 바꿉니다. 확인해 주시면 진행합니다.

**사용자:** 진행해.

## 설치

### 모든 에이전트 (skills CLI)

```bash
npx skills add aesopm/vague
```

감지된 에이전트(Claude Code, Codex 등)에 현재 프로젝트 기준으로 설치합니다. 전역 설치는 `-g`를 붙입니다. Claude Code에서는 `/vague`, Codex에서는 `$vague`로 호출합니다.

### Claude Code

```
/plugin marketplace add aesopm/vague
/plugin install vague@vague
```

호출: `/vague:vague <주제와 떠오르는 생각>`

수동 설치: `skills/vague/SKILL.md`를 `~/.claude/skills/vague/SKILL.md`에 두고 `/vague`로 호출합니다.

### Codex

```bash
codex plugin marketplace add aesopm/vague
codex plugin add vague@vague
```

새 세션을 열고 `$vague:vague <주제와 떠오르는 생각>`으로 호출합니다. Codex CLI의 `/`는 내장 명령 전용이라 `/vague`는 없습니다.

수동 설치: `skills/vague` 폴더를 `~/.codex/skills/vague`(전역)나 레포 안의 `.agents/skills/vague`에 복사하고 `$vague`로 호출합니다.

`skills/vague/agents/openai.yaml`이 암묵적 호출을 꺼 두어서, Codex는 직접 부를 때만 이 스킬을 씁니다. Claude Code에서는 `disable-model-invocation`이 같은 역할을 합니다.
